# 계속 새로 쓰는 장치

리추얼 기록·과제 목록·출석 파일을 읽어 **자기소개 사이트와 문서 3종(이력서·자기소개서·경력기술서)을 다시 만드는** 프로그램입니다.
새 기록을 넣고 한 번 돌리면 사이트의 숫자 칸과 능력별 문단이 갱신됩니다.

어느 사이트를 만들지는 `본문/사이트설정.json`의 `"트랙"` 값으로 정합니다.

| 트랙 값 | 만들어지는 사이트 | 문서 이름 |
|---|---|---|
| `backend` | `site-backend/index.html` (백엔드 개발자) | `문서/백엔드_*.md` |
| `cloud` | `site-cloud/index.html` (클라우드 엔지니어) | `문서/클라우드_*.md` |

## 돌리는 방법 (3단계)

1. **입력 파일을 넣는다** — 과제 화면의 「JSON으로 담기」로 받은 파일을 `입력/리추얼기록.json` 이름으로 저장합니다. 출석 숫자는 `입력/출석.json`에 적습니다.
2. **실행한다** — 이 폴더에서 아래 명령을 실행합니다.
   ```
   python build.py
   ```
3. **결과를 확인한다** — 사이트 `index.html`, `문서/` 3개, `제출물/`의 짧은 확인 방법·제출문, `마지막결과/숫자.json`·`문단후보.md`가 다시 만들어집니다. 브라우저에서 index.html을 열어 확인합니다.

필요한 것은 **Python 3.9 이상뿐**입니다. 설치할 외부 패키지가 없습니다(표준 라이브러리만 사용).

## 같은 입력이면 같은 결과가 나오는 이유

- 실행 중에 **AI를 호출하지 않습니다.** 필요한 API 키나 환경 변수가 없습니다.
- 사이트에 들어가는 문장은 `승인문장/능력별_장면.json`에서 `"승인": true`인 것만 읽습니다. 사람이 승인한 문장만 나갑니다.
- 숫자는 `입력/` 폴더의 파일에서만 셉니다.
- 결과물에 **실행 시각을 넣지 않습니다.** 기간 표시는 기록 파일 안의 날짜에서 가져옵니다.

## 리추얼 원본과 정제본 (개인정보 처리)

`입력/리추얼기록.json`(과제 화면에서 받은 원본, 아침·마무리에 적은 문장 전체)은 **저장소와 제출 ZIP 어디에도 들어가지 않습니다** (`.gitignore`, `묶기.py` 둘 다 제외). 대신 `build.py`를 실행하면 계산에 실제로 필요한 정보(날짜·아침 작성 여부·마무리 작성 여부·"일부" 표현 포함 여부)만 뽑아 `입력/리추얼기록.정제.json`을 자동으로 만들고, 이 정제본만 커밋·제출됩니다.

그래서 **원본이 없어도 정제본만 있으면 완전히 같은 숫자가 나옵니다.** 새 폴더에서 이 저장소(또는 제출 ZIP)를 그대로 풀어 `python build.py`를 돌리면, 정제본을 읽어 리추얼 숫자 칸을 그대로 재현합니다 — 원본을 다시 받을 필요가 없습니다.

원본을 새로 넣고 싶으면(예: 기록이 더 쌓였을 때) `입력/리추얼기록.json`에 덮어쓰고 다시 실행하면, 정제본이 새 원본 기준으로 다시 만들어집니다.

`python 점검.py`를 실행하면 장치를 한 번 더 돌려 결과 파일이 바뀌지 않는지 자동으로 비교합니다(BRA-C09).

## 함께 들어 있는 도구

| 파일 | 하는 일 |
|---|---|
| `build.py` | 사이트·문서(MD)·짧은 확인 방법·제출문을 다시 만듦 |
| `문서_docx.js` | 이력서·자기소개서·경력기술서를 Word 문서 한 파일로 만듦 (Node.js, `docx` 패키지 필요 — 선택) |
| `묶기.py` | `문서/`·`장치/`·`본문/`과 확인 방법·제출문·재현성 기록을 `제출물/제출_문서와장치.zip` 하나로 묶음 (비밀번호 없음, 리추얼 원본 제외) |
| `재현확인.py` | 같은 폴더 2회 + ZIP을 새 폴더에 풀어 1회 실행해 해시를 비교하고 `제출물/재현성_확인.md`를 씀 |
| `남길것.py` | 과제 카드의 "남길 것"을 `남길것/` 폴더에 번호순 파일로 모음 |
| `점검.py` | 과제 통과 기준 BRA-C01~C21과 "남길 것" 항목을 파일에서 직접 확인 |

### 제출 전 전체 순서

```
python build.py
node 문서_docx.js
python 묶기.py
python 재현확인.py
python 묶기.py
python 남길것.py
python 점검.py
```

`묶기.py`를 두 번 부르는 이유: `재현확인.py`는 방금 만든 ZIP으로 3차 실행을 하고, 그 결과로 새로 쓴 기록을 다시 ZIP에 담아야 하기 때문입니다.

## 폴더 구성

| 경로 | 내용 |
|---|---|
| `입력/리추얼기록.json` | 아침·마무리 기록 (과제 화면에서 받음) |
| `입력/리추얼기록.예시.json` | 기대하는 입력 형식 예시 |
| `입력/과제목록.json` | 과제별 상황·행동·결과·능력과 해당 트랙 |
| `입력/출석.json` | 출석 숫자 |
| `입력/검증숫자.json` | 다시 셀 필요 없는 확정 숫자(출처 포함) |
| `승인문장/능력별_장면.json` | 사이트에 나갈 인용문. 승인되지 않은 문장은 나가지 않음 |
| `템플릿/site.html.tmpl` | 사이트 틀 |
| `마지막결과/` | 마지막 실행 결과 (숫자.json, 문단후보.md) |

## 입력 형식

`리추얼기록.json`은 날짜·아침·마무리 칸이 있는 기록 목록이면 됩니다. 아침·마무리 값은 문자열이어도 되고, 화면처럼 여러 칸으로 나뉜 객체여도 읽습니다. 자세한 형태는 `입력/리추얼기록.예시.json`을 보세요.

입력 파일이 없으면 그 숫자 줄만 빠진 채로 사이트가 만들어지고, 실행할 때 어떤 파일이 없는지 알려줍니다.

## 새 폴더에서 처음부터 돌려보기

ZIP을 풀거나 저장소를 내려받은 뒤, `장치/`와 `본문/`이 나란히 있는 상태에서 실행합니다.

```
cd 새폴더/장치
python build.py
```

입력 파일과 본문이 함께 들어 있으므로 바로 같은 결과가 나옵니다.

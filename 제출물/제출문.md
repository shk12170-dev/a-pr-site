## AI와 나의 판단 세 줄

1. **AI에게 맡긴 일**: 흩어진 1~11번 과제 저장소 정리, 소설에서 자기소개 본문 초안 추출, 사이트·장치(build.py)·문서 생성과 실명·비밀값 검사를 맡겼습니다.
2. **내가 직접 판단한 일**: SOAR 알림 실습은 재료에서 빼고, 지원 목표를 백엔드 개발자로 정해 제출 사이트를 하나로 좁혔으며, 사실로 확인되는 문장만 쓰기로 하고 이야기 첫 문장은 직접 고쳐 썼습니다.
3. **AI 제안을 따르지 않은 일**: AI는 두 목표를 한 사이트 안에서 고르게 하자고 제안했지만, 목표가 다르면 첫 화면부터 달라야 한다고 판단해 따르지 않고 제출 사이트는 백엔드 버전 하나로, 클라우드 버전은 별도 폴더로 분리했습니다.

### 세부 근거

**AI에게 맡긴 일**

- 1~11번 과제 결과물이 흩어져 있던 GitHub 저장소를 찾아 과제 번호와 대조하고 재료 맵으로 정리한 일
- 3만 자 소설에서 고난·회복·지금 흐름과 세 능력에 해당하는 장면을 추려 자기소개 본문 초안을 쓴 일
- 사이트 템플릿과 장치(build.py) 구현, 이력서·자기소개서·경력기술서 생성
- 공개 URL이 로그인 없이 열리는지 확인하고, 제출물에 타인 실명·비밀값이 있는지 검사한 일
- 리추얼 원본에서 계산에 필요한 최소 정보만 남기는 정제 방식 구현과, 세 번 실행한 결과의 해시 비교

**내가 직접 판단한 일**

- SOAR 알림 자동화는 교육과정 실습이라 과제 재료에서 빼기로 한 것
- 지원 목표를 백엔드 개발자와 클라우드 엔지니어 두 갈래로 정한 뒤, 제출 사이트는 백엔드 버전 하나로 정한 것
- 사이트에 쓸 문장은 리추얼 기록 원문으로 확인되는 것만 쓰고, 소설에서 각색된 대화·묘사는 넣지 않기로 한 것
- 이야기 첫 문장을 직접 고쳐 쓰고, 공개할 연락 수단과 전역 연월을 직접 채운 것
- Vercel 배포와 최종 GitHub 업로드를 직접 수행하기로 한 것

**AI 제안을 따르지 않은 일**

- AI는 제출 URL이 한 개여야 한다는 이유로 사이트 하나 안에서 두 트랙을 고르게 하자고 제안했다. 목표가 다르면 첫 화면부터 달라야 한다고 판단해 따르지 않았고, 최종적으로 제출 저장소에는 백엔드 버전만 남기고 클라우드 버전은 별도 폴더로 분리했다.

## 완주 확인

- 소설에서 뽑은 자기소개 본문이 사이트 가운데에 있고, 각색된 대화·묘사는 넣지 않았습니다.
- 첫 화면에 이름과 “…한 사람”으로 끝나는 한 줄 소개가 있고, 그 안에 날짜가 있습니다.
- 숫자 칸 7개에 모두 출처를 적었습니다.
- 대표작 자리에 10번 논문 파일을 직접 올렸고, 13번 앱 자리를 비워 두었습니다.
- 과제 10개를 경력기술서에 능력별로 나눠 적었습니다.
- 장치를 두 번 돌리고 새 폴더에서도 돌려 결과가 같은 것을 확인했습니다.
- 제출물에 본인 이름과 공개하기로 한 연락 수단 외의 개인정보, 비밀번호·토큰·API 키는 없습니다.
